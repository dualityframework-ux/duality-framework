Automating the weekly variance write-up

How I use count data to prioritize inventory investigations, suggest causes to verify, and draft the next action.

Ian KachadorianOctober 20266 min read

The finding and the decision

Finding: in the synthetic sample, overages and shortages largely cancel in the net accuracy measure. Gross variance reveals discrepancies that still need investigation. Comparing counts also surfaces recurring discrepancies at the same locations.

Recommended action: investigate the largest dollar differences first. Recount the affected locations and review movement records before accepting a suggested cause or posting an adjustment. For recurring pairs, review the replenishment process as well as the current count.

What this demonstrates: a repeatable investigation workflow, implemented in JavaScript, Python and SQL. The sample checks that the rules behave as intended; it does not establish accuracy on unfamiliar counts, time saved or reduced inventory loss.

The problem

Part of my job in a distribution center is researching inventory discrepancies: finding the root cause behind each quantity or location variance and getting it corrected.

Most of that time is not detective work. It is recognizing patterns I have seen hundreds of times:

  • The same part is short 12 in one slot and over 12 in the slot next to it.
  • A box of 12 was counted as one.
  • Someone keyed 64 when the shelf held 46.
  • Two headlight bulbs that look identical are each off by the same amount, in opposite directions.

Pattern recognition that a person does the same way every week is exactly what a tool should do first. The person's time should go to the variances that do not fit a pattern.

The approach

I built Variance around the same four steps I follow by hand.

1. Measure both ways

Gross accuracy counts every dollar of variance. Net accuracy lets overages cancel shortages. Reporting only net hides problems, so Variance shows both.

A 99% net looks clean. The gross number shows more than $11,000 of absolute discrepancies to investigate; the count alone does not establish their causes.

2. Prioritize by dollars

A Pareto view ranks every line by absolute dollar impact. In the sample, 9 of 28 variance lines account for 80% of the gross. Those get looked at first.

3. Classify the likely cause

Each variance is checked against eight causes, in a deliberate order. The order matters because one real problem can look like two different ones:

OrderCauseWhy it comes here
1Mislocated stockA battery short at C-14-02 and over at C-15-04 is one move, not an empty slot and a found slot. Checking pairs first prevents two wrong write-ups.
2Unit of measureAn exact pack multiple, like 300 against 25, suggests a unit-of-measure issue to verify against the packaging and item setup. Requiring a difference of at least 5 units keeps small miscounts out.
3Transposed digitsSame digits, different order. Only checked for two-digit quantities and up.
4Look-alike swapTwo different SKUs in the same aisle, off by about the same amount in opposite directions.
5TimingMovement within a few days of the count, so a transaction may not have posted.
6–7Empty and foundOnly after the pairing checks, so they are not mistaken for halves of a move.
8Counter accuracyLast on purpose. Blaming the count is a judgment about a person, so it applies only to lines nothing else explains, and only for a counter whose variance rate is well above the team's.

4. Draft the explanation

For every line over the threshold, Variance writes a first draft in the same structure I use for every analysis: observation, mechanism, implication.

Observation. BAT-5100 (Battery, group 24F) at C-14-02: system 18, counted 6, a variance of −12 units (−$1,704.00).

Mechanism. The same item is short in one location and over by about the same amount in another, which points to a put-away or replenishment move that went to the wrong slot. The offsetting variance is at C-15-04.

Implication. Recount both locations and review the movement history. If the mislocation is confirmed, correct the locations through the appropriate transfer process and review the put-away that touched both slots.

The result

I tested it on a synthetic count of 164 lines with 14 problems planted in it: two mislocations, two unit-of-measure errors, a transposition, a look-alike swap, two timing issues, two empty locations, a found location, and one counter with a high error rate.

  • All 14 were classified correctly, and the counter was flagged. An automated test checks this on every change.
  • It also found something I did not plant: a serpentine belt over 3 in one aisle and short 3 in another. That came from the random noise in the sample, and it is exactly what a real offsetting pair looks like. Whether a 3-unit pair is worth a transfer is a judgment call, which is the point: the tool surfaces it and a person decides.
  • The four lines over $1,000 come with drafted write-ups ready to verify and paste.

The limits

  • These are rules, not a model. The tolerances (pairs within 10–15%, swaps in the same aisle) are judgment calls from experience. They are now adjustable in a settings panel, but someone still has to choose them.
  • Evidence depends on the export. With transaction history it can confirm some causes; without it, a variance only looks like a mislocation. Every draft is still a starting point to verify.
  • Timing needs data. The timing check only works if the export includes a last-movement date.
  • It has only seen synthetic data. No employer data was used to build or test it.

What I would build next

  1. Learn the tolerances from write-ups a person has confirmed, so the rules fit each building.

Update: transaction history is now built in. Load a file of moves, receipts and picks, and Variance checks it against each diagnosis. On the sample, the history matches the battery transfer (quantity and locations before the count), and supports six other lines, including both timing hypotheses. A matching transfer does not prove the cause. For the alternators it shows a putaway from the dock rather than from the paired slot, which is exactly the kind of thing worth checking before writing it up. Matched and supported lines carry an Evidence line in the drafted write-up.

Update: Variance now compares counts. Load an earlier count of the same locations and it shows how accuracy moved, which causes grew or shrank, and which lines are off again. On the sample, gross accuracy fell from 96.82% to 94.32%. Nine lines were off in both counts, worth $4,682 this time, or 40% of gross. The battery pair was mislocated in the same two slots both months, 8 units then and 12 now. One transfer fixes the count; the repeat says the replenishment process keeps putting batteries in the wrong slot. That is the finding a single count can't show.

Update: the recount sheet is now built. Variance lists every location worth recounting in walking order, aisle by aisle in alternating directions, with a blind-count option that hides the system quantity so it can't bias the recount.

Built with plain JavaScript and no dependencies. The analysis logic lives in one file of pure functions, tested in Node and run on every push with GitHub Actions. Files never leave the browser.
