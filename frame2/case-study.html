Case study

How does the record compare with run differential?

Comparing actual wins with a run-differential estimate across 58 Red Sox seasons: what the comparison shows, data mistakes I corrected, and what the model cannot establish.

Ian KachadorianOctober 20265 min read

The problem

Standings summarize wins and losses. Comparing them with run differential gives another view of the same season and highlights differences worth investigating. This comparison does not establish what caused those differences or predict the next season.

frame² compares actual wins with a simple estimate based on run differential: runs scored minus runs allowed. The gap is a model residual, meaning the part of the record this formula does not explain. It can reflect chance, omitted factors and limitations of the formula.

The approach

1. One row per season

The dataset covers every Red Sox season from 1967 to 2024: wins and losses, run differential, team OPS, OBP and SLG, ERA and FIP, the playoff result, the manager, the key players, and a one-sentence summary of what drove the season.

2. Tag each season against the run-differential estimate

Each season gets an expected win total from its run differential, using the rule of thumb that about 10 runs are worth one win: 81 + run diff ÷ 10. Both the record and the expectation are scaled to 162 games, to put seasons of different lengths on the same scale. Scaling does not give a short season the same amount of evidence as a full season. Win gap means actual win pace minus the estimate; it is not a direct measurement of luck.

A simple formula with explicit tag rules makes the calculation easy to inspect. The first version used raw-win thresholds, and the timeline and the app had drifted to two different definitions of signal. Both now come from this one rule.

3. Explain it the same way every time

Every insight follows observation, mechanism, implication. For 2024: the team finished 81–81; run differential was +4, so the win pace was close to the estimate. This comparison alone does not identify a cause or a roster decision.

4. Ship it as tools

The Python and Streamlit app has a season explorer, an era comparison, a franchise timeline, a post generator and a manual game simulator. Automated tests run in CI. The live timeline is generated directly from the canonical CSV. Seven ERA corrections follow archived MLB Stats API responses; four unsupported contributor names were removed. Review the source audit and correction log. MLB doesn't publish team FIP, so I compute it from MLB's own counts with the standard formula. Doing that showed the earlier FIP values were unreliable: only 10 of 58 were within 0.05 of the computed figure, so all 58 were replaced, with every input recorded. FIP stays out of the radar charts. Roster membership does not establish relative contribution, and narratives remain curated interpretations.

  • 1985 had the largest negative win gap under this formula: the estimate was 89 wins, against a .500 record. 2002 had an estimate of about 100 wins and missed the playoffs.
  • The 2007 champions finished below the estimate, about six wins below the estimate from a +210 run differential.
  • 1975 had the largest positive win gap among the pennant seasons, about six wins above the estimate.
  • Eight seasons rate as signal, including 1977 and 1978, which never reached the playoffs, and 2003 and 2008, which lost in the ALCS. The tag describes the rule, not a proven championship-level roster.
  • Scaling changes conclusions. 1995 went 86–58: under raw-win rules it looked underperformed, but its 97-win pace was about five wins ahead of its run differential.
  • Win pace and expected wins correlate at 0.91 across all 58 seasons. This is a same-season association, not a test of future prediction or proof that the remaining gap is random.

A mistake I caught. The dataset marks every pennant season as "world series." Several outputs read that as a title, so the timeline claimed six championships and treated 1967, 1975 and 1986 as wins. The Red Sox actually made seven trips and won four. I fixed it with one list of title seasons that every page now reads from, and added a test that fails if titles are ever not a subset of World Series seasons. The lesson: a label in the data is not the same as its meaning, and anything shown as a fact needs a check behind it.

The limits

The gap is not a diagnosis. Before attributing it to luck, compare alternative formulas and examine game-level results. This analysis does neither, so its tags are descriptive rather than causal.

  • The ±4 band is a judgment. 2018 (108 wins, +229) lands just over it at +4.1 and reads as overperformed, though it was an elite team either way.
  • Ten runs per win is a rule of thumb. The dataset has run differential but not runs scored and allowed, so the full Pythagorean formula isn't possible yet.
  • Run differential is a simple process measure. It ignores schedule strength and the league's run environment.

What I would build next

  1. Add runs scored and allowed to the data, so expected wins can use the full Pythagorean formula instead of the runs-per-win rule below.
  2. Host the full Streamlit app so every page is live, not just the timeline.
