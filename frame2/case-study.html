Case study

Did they earn that record, or get lucky?

Separating process from result across 58 Red Sox seasons: the rules, what they found, a data mistake I caught and fixed, and where the model falls short.

Ian KachadorianOctober 20265 min read

The problem

Standings record outcomes. They do not tell you whether a team earned them. A 92-win season can come from a dominant roster or from winning an unusual number of close games, and the two predict very different futures.

frame² rests on one idea: result = process + variance. Wins are the result. Run differential, the runs a team scored minus the runs it allowed, is the best simple measure of process. When the two disagree, variance is usually the reason.

The approach

1. One row per season

The dataset covers every Red Sox season from 1967 to 2024: wins and losses, run differential, team OPS, OBP and SLG, ERA and FIP, the playoff result, the manager, the key players, and a one-sentence summary of what drove the season.

2. Tag each season with plain rules

TagRuleReading
Signal≥ 95 wins and ≥ +150 run diffElite process matched an elite record
Underperformed≥ +75 run diff, < 90 winsThe process pointed higher than the record
Overperformed< +25 run diff, ≥ 92 winsThe record outran the process
BalancedEverything elseRecord and process told the same story

Rules instead of a model was a deliberate choice: anyone can check a tag by looking at two numbers.

3. Explain it the same way every time

Every insight follows observation, mechanism, implication. For 2024: the team finished 81–81; run differential was +4, so the record matched the process; an average team got an average result, with nothing to chase or excuse.

4. Ship it as tools

The Python and Streamlit app has a season explorer, an era comparison, a franchise timeline, a post generator and a live game module that reads the MLB Stats API. It is covered by 215 automated tests that run on every push. The live timeline is generated from the same data.

What it found

  • Six seasons rate as signal, and four of them won the World Series: 2004, 2007, 2013 and 2018. The other two, 2003 (+152) and 2008 (+151), had championship-level process and lost in the ALCS. Same process, different variance.
  • Four seasons underperformed: 1973, 1985, 1988 and 1995. The 1985 team went 81–81 with a +80 run differential, a better team than its record.
  • No season clearly overperformed under these rules. The record rarely ran far ahead of the run differential.
  • Across all 58 seasons, wins and run differential correlate at 0.74. Process explains most of the record, and the rest is what makes baseball interesting.

A mistake I caught. The dataset marks every pennant season as "world series." Several outputs read that as a title, so the timeline claimed six championships and treated 1967, 1975 and 1986 as wins. The Red Sox actually made seven trips and won four. I fixed it with one list of title seasons that every page now reads from, and added a test that fails if titles are ever not a subset of World Series seasons. The lesson: a label in the data is not the same as its meaning, and anything shown as a fact needs a check behind it.

The limits

  • Shortened seasons are not normalized. The rules use raw wins, so the strike years and 2020's 60 games are judged against full-season thresholds. In 1995 the team went 86–58, a 96-win pace, but is tagged underperformed because 86 is under 90.
  • The thresholds are hand-set. +150 for signal is a judgment, not a fitted value.
  • Two definitions of signal exist in the project. The interactive timeline uses a broader rule (95 wins and +80) than the analysis engine. They need to agree.
  • Run differential is a simple process measure. It ignores schedule strength and the league's run environment.

Update: expected wins, scaled to 162 games

Since writing this, I added the first fix. Every season now gets an expected win total from its run differential, using the rule of thumb that about 10 runs of differential are worth one win, scaled to 162 games. Luck is the gap between the team's win pace and that expectation.

  • 1985 was the unluckiest season in the data: a team worth 89 wins finished at .500.
  • 2002 played like a 100-win team and missed the playoffs.
  • 1975 was the luckiest pennant, about six wins ahead of its run differential.
  • 1995 shows why scaling matters. The original rules tag it underperformed because 86 wins is under 90. Over 162 games it was a 97-win pace, about five wins ahead of its run differential. Same season, opposite conclusion.

Win pace and expected wins correlate at 0.91 once seasons are scaled, against 0.74 for raw wins and run differential. The luck table is in the app's process-vs-result page, with tests behind the math.

What I would build next

  1. Add runs scored and allowed to the data, so expected wins can use the full Pythagorean formula instead of the runs-per-win rule below.
  2. Settle one definition of signal and use it everywhere.
  3. Host the full Streamlit app so every page is live, not just the timeline.
